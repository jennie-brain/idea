# 0. Project Definition

- **프로젝트명:** 미래지출 결제설계 서비스 *(Working Title: Planned Spend Payment Planner)*
- **프로젝트 유형:** 신규 핀테크 서비스 / 금융 의사결정 지원
- **한 줄 정의:**  
  사용자의 현재 소비와 향후 고액지출 계획을 함께 분석하여, 보유 카드와 신규 카드 후보·할부·혜택 조건·결제시점을 비교하고 **각 예정 지출을 무엇으로 어떻게 결제할지 사전에 설계하도록 돕는 서비스**
- **기획 기준일:** 2026-08-13
- **작성자 / 팀:** JENNIE / AI-PM-study

> **잠정 Product Vision**
>
> 단순히 “좋은 카드를 추천하는 서비스”가 아니라,  
> **미래에 예정된 소비 변화에 맞추어 결제수단 포트폴리오를 설계하는 Payment Decision Support Service**를 지향한다.
>
> 신혼·입주 과정의 가전·가구 구매는 초기 문제 검증을 위한 Beachhead Use Case이며, 이후 이사·인테리어·여행·출산 등 다른 Planned High-Value Spending Event로의 확장 여부를 검토한다.

# 1. Background & Problem

## 1.1 Background

### 프로젝트 검토 계기

- **[FACT]** 2025년 국내 혼인 건수는 240,326건으로 전년 대비 8.1% 증가했다.
- **[FACT]** KB국민카드가 결혼식장 업종에서 월 300만원 이상 이용한 고객 2만2천 명의 카드 데이터를 분석한 결과, 결혼 3~4개월 전부터 가구·가전·가정용품 지출이 증가했고 결혼 1~2개월 전에 높은 비중을 보였다. 결혼 1개월 전 카드 이용금액은 1년 전 대비 약 20% 증가했고 평균 약 227만원이었다.
- **[INFERENCE]** 결혼·신혼집 마련은 평상시 소비패턴과 다른 복수의 고액지출이 짧은 기간에 집중되는 대표적인 Life Event다.

### 현재 서비스·산업 상황

- **[FACT]** 뱅크샐러드는 2026년 사용자의 최근 1년 마이데이터 소비내역을 분석하여 실제 카드 혜택과 추천카드 사용 시 예상 혜택을 비교하고, 캐시백·연회비 지원까지 포함해 신규 카드를 추천하는 서비스를 출시했다.
- **[FACT]** 카드고릴라 등 카드 비교서비스에서는 혼수·결혼 준비 상황에 맞춘 카드 추천 콘텐츠가 이미 제공되고 있다.
- **[FACT]** 헥토이노베이션의 더쎈카드는 2023년 사용자가 향후 소비가 증가할 항목을 선택하면 해당 소비에 유리한 카드와 현재 카드의 혜택을 비교하는 기능을 제공했고, 장기적으로 모든 결제수단을 설계하는 소비계획 서비스를 지향했다.
- **[FACT]** 그러나 헥토이노베이션의 2026년 사업보고서에는 더쎈카드가 당기 중 서비스를 종료했다고 기재되어 있다.

### 현재 해석

- **[INFERENCE]** `과거 소비 → 카드 추천` 시장에는 이미 강한 대체재가 존재한다.
- **[INFERENCE]** `미래 소비 카테고리 → 카드 추천` 역시 완전히 새로운 개념은 아니다.
- **[HYPOTHESIS]** 아직 검증할 가치가 있는 영역은 **구체적인 미래 구매계획을 기준으로 보유카드와 신규카드를 함께 배치하고, 구매건별 결제수단·시점까지 설계하는 End-to-End 의사결정 과정**이다.
- **[HYPOTHESIS]** 더쎈카드의 종료는 이 문제의 수요·사용빈도·사업성에 구조적 한계가 있을 가능성을 보여주는 반증 자료일 수 있다.

# 2. Target & Usage Context

## 2.1 Core Target

### 핵심 사용자 — Proto Persona

**[HYPOTHESIS]**

> 향후 1~3개월 내 여러 건의 고액 구매가 예정되어 있고,  
> 결제 전 카드·할부·판매처 혜택을 적극적으로 비교할 의향이 있는 개인 소비자

### Beachhead Segment

> **신혼·입주 과정에서 가전·가구 등 여러 고액품목을 구매할 예정인 카드 사용자**

### 행동 특성

- 구매할 품목과 대략적인 예산이 존재
- 여러 판매처에서 견적을 비교
- 신용카드를 한 장 이상 보유
- 필요하면 신규카드를 추가 발급할 의향이 있음
- 할인·캐시백·마일리지·무이자할부 등의 경제적 차이에 민감

### 제외 사용자

- 일상적인 소액 소비 카드추천만 원하는 사용자
- 단일 제품의 최저가만 찾는 사용자
- 결제방법 비교 의사가 거의 없는 사용자
- 사업자·법인 구매 사용자
- 계획할 수 없는 긴급지출 사용자

## 2.2 Usage Context

### When

- 결혼·입주·이사 등 Life Event가 확정된 이후
- 구매 품목과 예산이 구체화되기 시작하는 시점
- 실제 결제를 실행하기 전

### Trigger

고객의 실제 진입 질문은 다음 형태를 가정한다.

- “다음 달에 신혼집 가구랑 가전을 많이 사는데 어떤 카드가 좋아?”
- “가전 800만원 살 건데 카드 하나 새로 만드는 게 이득일까?”
- “지금 가지고 있는 카드로 혼수 결제해도 괜찮아?”
- “무이자할부하고 캐시백 중 어떤 게 더 이득이야?”
- “냉장고, 세탁기, 소파를 각각 어떤 카드로 결제해야 해?”
- “이번 달과 다음 달로 나눠 사면 더 이득일까?”
- “앞으로 쓸 돈까지 고려해서 카드 구성을 다시 짜고 싶어.”

> **[HYPOTHESIS]** 이러한 Trigger 문구가 실제 검색·커뮤니티·상담 과정에서 반복되는지가 향후 검증 대상이다.

### Goal

> **이미 예정된 소비를 어떤 결제수단에 어떻게 배분하면 가장 합리적인지 결제 전에 결정한다.**

### Constraint

- 총 구매예산
- 구매예정 시점
- 보유카드
- 신규발급 허용 장수
- 카드 한도
- 연회비
- 전월실적
- 월/건별 혜택한도
- 가맹점/업종 조건
- 프로모션 대상 여부
- 일시불 / 할부
- 사용자가 감당할 수 있는 월 상환액
- 카드 관리 복잡도

# 3. Project Goal & Success Criteria

## 3.1 Project Goal

- **[대상 Problem ID: P-01, P-02]**

### 사용자 관점

미래 고액지출에 대해 여러 카드·판매처·결제조건을 직접 분산 탐색하지 않고 **비교 가능한 결제 시나리오와 실행 가능한 Payment Plan을 확보**하게 한다.

### 사업 관점

카드 자체에 대한 일반적 추천보다 **고액지출 직전이라는 강한 Trigger가 실제 제품 사용동기로 작동하는지 검증**한다.

### 운영 / 리스크 관점

카드·프로모션 정보를 잘못 적용하여 과대 혜택을 제시하지 않고, 모든 계산의 조건과 근거를 사용자가 확인할 수 있게 한다.

# 4. Solution Direction

## 4.1 As-is

- **[대상 Problem ID: P-01, P-02]**

```text
Life Event 발생
→ 필요한 물건과 예산 정리
→ 판매처별 견적 탐색
→ 카드추천/프로모션 검색
→ 보유카드 조건 확인
→ 신규카드 발급 여부 판단
→ 할인/적립/할부 조건을 직접 계산
→ 구매건별 결제수단 결정
→ 실제 구매
```

### 잠정 Pain

- 정보가 판매처·카드사·비교플랫폼·커뮤니티에 분산
- 카드별 조건과 프로모션 적용조건이 서로 다름
- 카드 한 장의 혜택이 아니라 **전체 구매 조합**을 계산해야 함
- 미래 지출이 평상시 소비와 크게 달라 과거 소비 기반 추천의 효용이 낮아질 수 있음

---

## 4.2 Solution Principle

- **[대상 Problem ID: P-01, P-02]**

### 핵심 해결 원리

> **카드를 추천하는 대신 미래 소비계획을 먼저 모델링하고, 사용자의 제약조건 안에서 여러 결제 시나리오를 계산해 실행 가능한 Payment Plan을 제시한다.**

### 보조 해결 원리

1. **Past → Future:** 현재 소비를 기준선으로 사용하되 미래 지출을 직접 수정
2. **Product → Portfolio:** 카드 한 장이 아니라 보유+신규 카드 조합을 계산
3. **Recommendation → Design:** 추천 후 각 카드에 미래 지출 역할을 부여
4. **Maximum → Practical:** 최대 혜택뿐 아니라 카드 수·연회비·할부·관리복잡도 고려
5. **Black Box → Explainable:** 각 추천의 계산조건과 근거를 공개

---

## 4.3 To-be

```text
현재 소비/보유카드 확인
→ 미래 Life Event 선택
→ 예정 지출항목·금액·시점 입력
→ 예산 목표 및 제약조건 수정
→ 여러 Payment Scenario 계산
→ 현재 카드 유지 / 신규 발급안 비교
→ 추천안 선택
→ 미래 카드 역할 설계
→ 구매건별 결제계획 생성
→ 실제 구매
→ [향후] Event 종료 후 카드 유지 여부 재평가
```

| Problem | 변경 원리 | 기대 변화 |
|---|---|---|
| P-01 | 분산된 조건을 한 시나리오에서 비교 | 탐색·계산 부담 감소 |
| P-02 | Future Spend를 직접 입력해 추천 재계산 | 미래 소비와 추천의 정합성 향상 |

---

## 9.2 Validation Method

### Phase 1 — Problem Discovery

- 최근 혼수·입주 구매 경험자 인터뷰
- 향후 1~3개월 내 고액구매 예정자 인터뷰

실제 예정 구매목록을 받아 사람이 카드 조건을 계산해:

- 기존 방식
- 현재카드 유지
- 신규카드 1장 추가
- 구매 배분 변경

시나리오를 제공하고 실제 의사결정 가치 측정

### Phase 3 — Prototype

`Future Spend → Scenario → Card Design → Payment Plan` 흐름 검증
